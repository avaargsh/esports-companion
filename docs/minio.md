# MinIO Image Storage

The API can use MinIO for user avatars, player showcase images, and order evidence images. The backend issues short-lived presigned PUT URLs; clients upload image bytes directly to MinIO and store the returned object key or public URL in the relevant business record.

## Local Deployment

MinIO is optional for the default demo stack. Start it separately when you need to test image upload:

```bash
docker run --name esports-minio --rm \
  -p 19000:9000 -p 19001:9001 \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  minio/minio:RELEASE.2025-09-07T16-13-09Z server /data --console-address ":9001"
```

Default local endpoints for that command:

```text
MinIO API:     http://localhost:19000
MinIO Console: http://localhost:19001
Access key:    minioadmin
Secret key:    minioadmin
Bucket:        esports-images
```

For local browser or phone direct upload, `MINIO_ENDPOINT` must be reachable by the uploading client because the presigned URL is generated from that endpoint. If your phone tests through LAN IP `192.168.1.33`, use:

```env
MINIO_ENDPOINT=192.168.1.33:19000
MINIO_PUBLIC_URL=http://192.168.1.33:19000
```

Then rebuild/restart the API container so the MinIO SDK dependency and environment settings are loaded:

```bash
docker compose up --build -d api
```

## Environment Variables

```env
MINIO_ENDPOINT=localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET_NAME=esports-images
MINIO_SECURE=false
MINIO_PUBLIC_URL=http://localhost:9000
MINIO_PRESIGNED_EXPIRES_SECONDS=900
```

`MINIO_ENDPOINT` is the host used by the SDK to create presigned upload URLs. `MINIO_PUBLIC_URL` is used for public image read URLs returned by `/get-url`.

The Dockerized API reads these values from the repository root `.env` through `docker-compose.yml`. For direct browser or Mini Program upload, choose an endpoint that both the API container and the client can reach, such as a LAN IP or public HTTPS host.

## API Contract

### Get Upload URL

```http
POST /api/minio/get-upload-url
Content-Type: application/json

{"filename": "avatar.png"}
```

Response:

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "uploadUrl": "http://localhost:9000/esports-images/images/...png?...",
    "key": "images/...png"
  }
}
```

The frontend uploads the raw binary image with HTTP PUT to `uploadUrl`. Use the image MIME type as `Content-Type` when uploading.

### Get Public URL

```http
GET /api/minio/get-url?key=images/example.png
```

Response:

```json
{
  "code": 0,
  "message": "ok",
  "data": {"url": "http://localhost:9000/esports-images/images/example.png"}
}
```

### Delete Image

```http
DELETE /api/minio/delete-img?key=images/example.png
```

Response:

```json
{"code": 0, "message": "ok", "data": {"deleted": true}}
```

The same endpoints are also available under `/api/v1/minio/*` for versioned API clients.

## Security Notes

Only public read access is applied to the bucket. Do not grant anonymous write, delete, or list permissions to the bucket. Uploads should go through short-lived presigned PUT URLs generated by the backend after application-level authorization.

For staging and production:

- Use strong MinIO credentials, not the local defaults.
- Keep MinIO write credentials server-side only. Never put access keys or secret keys in the Mini Program.
- Put MinIO behind HTTPS and set `MINIO_SECURE=true` when the endpoint uses TLS.
- Use a public CDN or reverse proxy URL for `MINIO_PUBLIC_URL` if clients need internet access to images.
- Keep presigned upload expiration short, such as 5-15 minutes.
- Consider separate buckets or prefixes if avatars, player showcase images, and order evidence need different retention or privacy policies.
